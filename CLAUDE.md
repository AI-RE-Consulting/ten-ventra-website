AI Consulting Company Website
Project Purpose

This project is an informational website for an AI consulting company.
The website communicates services, expertise, case studies, and contact information to potential clients.

Primary goals:

Clearly explain services and value proposition

Generate consulting leads

Showcase past work and expertise

Provide a professional and modern web presence

This is not a complex web app. Keep architecture simple and maintainable.

Development Philosophy

Prefer simplicity over cleverness.

Avoid unnecessary frameworks or complexity.

Keep components reusable and modular.

Changes must not break existing pages.

SEO and performance matter.

Content clarity is more important than animations.

Site Structure

Typical pages include:

Home

Services

Case Studies / Projects

About

Blog or Insights (optional)

Contact

All pages should reuse common components where possible.

Content Philosophy

Content should:

Be clear and professional

Avoid buzzwords

Explain technical concepts simply

Focus on business outcomes

Show credibility and expertise

Avoid hype language. Prefer concrete results and clarity.

Claude Code Editing Rules

When modifying code:

Do NOT rewrite large sections unless requested.

Make minimal safe changes.

Keep naming conventions consistent.

Preserve formatting and project structure.

Avoid introducing dependencies without approval.

Maintain responsive design behavior.

Ensure accessibility basics remain intact.

Component Guidelines

Components should:

Have single responsibilities

Be reusable

Avoid tight coupling

Keep styling consistent

Avoid inline complexity

Shared layout pieces must stay centralized.

Styling Principles

Clean, modern, professional look

Minimal visual clutter

Strong typography hierarchy

Good spacing

Mobile-friendly by default

Avoid excessive animations or gimmicks.

SEO & Performance

Pages should include:

Proper page titles

Meta descriptions

Semantic HTML

Fast load performance

Image optimization

Avoid heavy scripts.

Content Expansion Strategy

Future additions may include:

Blog posts

Case studies

Technical articles

Tools or demos

Client resources

Structure content so expansion is easy.

Safe Refactoring Rules

Claude should:

Flag major structural issues before changing them.

Suggest improvements incrementally.

Avoid dramatic rewrites.

Code Quality Expectations

Prefer:

Readable code

Clear naming

Modular components

Minimal duplication

Avoid:

Dead code

Over-abstraction

Premature optimization

When Claude Should Ask Before Acting

Claude should pause and ask when:

Changing architecture

Introducing new dependencies

Renaming major components

Modifying routing structure

Altering build system

Long-Term Vision

The site may later support:

Lead capture automation

AI tool demos

Final Principle

This is a business website, not a technical playground.

Clarity > complexity.
Conversion > cleverness.
Maintainability > novelty.
